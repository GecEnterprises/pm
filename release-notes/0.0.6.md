# pm 0.0.6

- **`pm-debug` — a development build that runs beside your real pm.** `cargo pmd`
  (or the `pm-debug` binary) opens a visually distinct window — blue icon,
  `pm-debug` in the title — with its own taskbar identity, so debugging pm no
  longer means closing the copy holding your actual tickets. A coding agent that
  launches pm to test a change now opens something you can tell apart at a
  glance. `pm-debug --mcp` runs the MCP server against the debug GUI.
- **Forward-compatibility guard for the ticket store.** An older pm opening a
  `.pm/pm.json5` written by a newer pm now shows it read-only and refuses to save,
  instead of silently dropping fields it doesn't recognise and rewriting the
  truncated file on the next edit. Update pm and it saves normally again.
- **The MCP server explains itself to coding agents.** Its instructions now cover
  *when* to reach for pm — check for an existing ticket before starting work,
  close what you finish, record scoping notes and dead ends as comments, attribute
  your authorship — rather than just listing the tools. It also reports its real
  name and version in the handshake.
- Internal: `pm-core` now exposes ticket field mutators (title, description,
  priority, labels, assignee) to the GUI, which the MCP `edit_ticket` tool could
  already reach — groundwork for editing those fields inline in the Tickets pane.
- `pm --setup`: narrowed a Windows Terminal / ConPTY input race where a stray
  Enter from the `irm | iex` install command could be consumed by the first y/n
  prompt.
